# Система управління ремонтною майстернею електроніки

Курсовий проект для керування ремонтами електроніки. Система дозволяє реєструвати замовлення, контролювати етапи ремонту, вести облік деталей, завершувати ремонт із розрахунком вартості та надсилати клієнтам Email/SMS-сповіщення.

## Основні можливості

- Авторизація працівників через JWT.
- Реєстрація замовлення на ремонт.
- Контроль статусів: `прийнято`, `діагностика`, `ремонт`, `виконано`, `видано`.
- Облік клієнтів, пристроїв, майстрів і використаних деталей.
- Автоматичне списання деталей зі складу при завершенні ремонту.
- Розрахунок суми до оплати: робота майстра + використані деталі.
- Email-сповіщення з оновленим дизайном і сумою до оплати.
- SMS-сповіщення через Twilio при прийнятті та виконанні замовлення.
- Автоматичне створення структури бази даних при старті сервера.

## Налаштування сервера

Перейдіть у папку сервера:

```bash
cd server
npm install
```

Створіть файл `.env` на основі `.env.example`:

```env
DB_USER=postgres
DB_PASSWORD=your-postgres-password
DB_HOST=localhost
DB_PORT=5432
DB_NAME=repair_workshop
DB_ADMIN_DATABASE=postgres
DB_AUTO_CREATE=true
PORT=5000
JWT_SECRET=replace-with-long-random-secret
DEFAULT_USER_PASSWORD=123456

EMAIL_USER=your-email@gmail.com
EMAIL_PASS=your-gmail-app-password

TWILIO_ACCOUNT_SID=AC...
TWILIO_AUTH_TOKEN=...
TWILIO_PHONE_NUMBER=+1...
```

Важливо: `.env` не потрібно комітити в Git, бо там зберігаються паролі та токени.

## База даних

PostgreSQL має бути встановлений і запущений. При старті сервер:

- підключається до PostgreSQL;
- якщо `DB_AUTO_CREATE=true`, пробує створити базу `DB_NAME`;
- створює таблиці, якщо їх ще немає;
- додає стартових майстрів, запчастини та користувачів;
- не видаляє існуючі замовлення або клієнтів.

Таблиці бази даних:

- `clients` - клієнти;
- `devices` - пристрої клієнтів;
- `orders` - ремонтні замовлення;
- `spare_parts` - склад деталей;
- `order_parts` - використані деталі в замовленні;
- `users` - користувачі системи;
- `masters` - майстри.

## Стартові користувачі

Якщо таблиця `users` порожня, сервер створює користувачів:

| Логін | Роль |
| --- | --- |
| `admin` | `адмін` |
| `master1` | `майстер` |
| `manager1` | `менеджер` |

Пароль береться зі змінної `DEFAULT_USER_PASSWORD`. За замовчуванням: `123456`.

## API

Основні маршрути:

- `POST /api/auth/login` - вхід у систему;
- `GET /api/auth/me` - перевірка поточного користувача;
- `GET /api/orders` - список замовлень;
- `POST /api/orders` - створення замовлення;
- `PUT /api/orders/:id/status` - зміна статусу;
- `PUT /api/orders/:id/complete` - завершення ремонту з ціною та деталями;
- `DELETE /api/orders/:id` - видалення замовлення;
- `GET /api/parts` - список деталей;
- `POST /api/parts` - додавання деталі;
- `PUT /api/parts/:id` - оновлення кількості;
- `DELETE /api/parts/:id` - видалення деталі;
- `PUT /api/clients/:id` - оновлення телефону або email клієнта.

## SMS та Email

SMS надсилається тільки у двох випадках:

- при створенні нового замовлення;
- при завершенні ремонту.

Email надсилається при зміні статусу та при завершенні ремонту. Лист при завершенні містить суму до оплати.

## Сценарій демонстрації

1. Увійти як `admin`.
2. Створити нове замовлення з телефоном клієнта.
3. Показати, що замовлення отримало статус `прийнято`.
4. Перевести замовлення в `діагностика` або `ремонт`.
5. Відкрити завершення ремонту.
6. Додати вартість роботи та використані деталі.
7. Завершити ремонт.
8. Показати суму до оплати, списання деталей і Email/SMS-сповіщення.
