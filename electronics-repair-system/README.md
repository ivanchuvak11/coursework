# Смарт лайф — система управління ремонтною майстернею електроніки

Курсовий проєкт для обліку ремонтів електроніки. Система дозволяє реєструвати замовлення, контролювати етапи ремонту, призначати майстрів, вести склад запчастин, списувати використані деталі, формувати фінансові показники та надсилати клієнтам Email/SMS-сповіщення.

## Варіант роботи

**Варіант №9. Система управління ремонтною майстернею електроніки**

Основна проблема: ремонтні майстерні мають труднощі з контролем етапів ремонту, обліком деталей та звітністю.

Реалізовані вимоги:

- реєстрація замовлень на ремонт;
- контроль стану ремонту: `прийнято`, `діагностика`, `ремонт`, `виконано`, `видано`;
- облік використаних деталей;
- інтеграція з SMS-сповіщеннями для клієнтів;
- захист клієнтських даних через авторизацію, JWT і розмежування ролей;
- база даних PostgreSQL з таблицями клієнтів, пристроїв, замовлень, деталей, користувачів, майстрів, історії статусів і заявок на деталі.

## Основні можливості

- Вхід у систему через JWT.
- Ролі: адміністратор, менеджер, майстер.
- Панель замовлень з пошуком, фільтрами, пагінацією та деталями замовлення.
- Створення нового замовлення з клієнтом і пристроєм.
- Призначення відповідального майстра.
- Для майстрів показуються тільки їхні замовлення.
- Майстри мають доступ до клієнтів і складу в режимі перегляду.
- Склад запчастин з пошуком, сортуванням, зміною кількості та видаленням.
- Заявки майстрів на замовлення деталей.
- Сповіщення для адміністратора/менеджера про заявки на деталі.
- Обробка заявки: можна відкрити форму додавання нової деталі з уже підставленою назвою.
- Завершення ремонту з розрахунком вартості роботи та використаних деталей.
- Автоматичне списання деталей зі складу після завершення ремонту.
- Фінансова сторінка з оцінкою доходу, вартістю складу та калькулятором середнього чека.
- Значення з калькулятора середнього чека підставляється у форму завершення ремонту.
- Звіти за замовленнями, майстрами, доходом і використаними деталями.
- Email-лист для клієнта з оновленим дизайном і сумою до оплати.
- SMS через Twilio при прийнятті та виконанні замовлення.
- Світла/темна тема та згортання бокового меню.

## База даних

Використовується PostgreSQL. При запуску сервер:

- підключається до PostgreSQL;
- за потреби створює базу даних;
- створює таблиці, якщо їх ще немає;
- додає стартових користувачів, майстрів і базові запчастини;
- не видаляє вже наявні замовлення або клієнтів.

Основні таблиці:

- `clients` — клієнти;
- `devices` — пристрої клієнтів;
- `orders` — ремонтні замовлення;
- `spare_parts` — склад запчастин;
- `order_parts` — використані деталі в замовленнях;
- `order_status_history` — історія зміни статусів;
- `part_requests` — заявки майстрів на деталі;
- `users` — користувачі системи;
- `masters` — майстри.

## Ролі та доступ

| Роль | Можливості |
| --- | --- |
| `адмін` | Бачить усі замовлення, клієнтів, склад, фінанси, звіти, налаштування. Може створювати й видаляти замовлення, керувати складом, призначати майстрів, обробляти заявки на деталі. |
| `менеджер` | Бачить усі замовлення, клієнтів, склад, фінанси, звіти й налаштування. Може створювати замовлення, редагувати клієнтів, керувати складом, призначати майстрів і обробляти заявки. |
| `майстер` | Бачить тільки призначені йому замовлення, клієнтів за своїми замовленнями, склад у режимі перегляду та налаштування. Може змінювати статус своїх замовлень до `виконано` і створювати заявки на деталі. |

Майстрам не доступне видання замовлення клієнту. Статус `видано` встановлює адміністратор або менеджер.

## Стартові користувачі

Сервер створює стартових користувачів, якщо їх ще немає:

| Логін | Роль |
| --- | --- |
| `admin` | `адмін` |
| `manager1` | `менеджер` |
| `master1` | `майстер` |
| `master2` | `майстер` |
| `master3` | `майстер` |

Пароль задається змінною `DEFAULT_USER_PASSWORD`. За замовчуванням: `123456`.

## Налаштування

Потрібно встановити:

- Node.js;
- npm;
- PostgreSQL.

Для Email потрібен Gmail App Password. Для SMS потрібен акаунт Twilio і куплений номер або Messaging Service.

Створіть файл `server/.env`:

```env
DB_USER=postgres
DB_PASSWORD=your-postgres-password
DB_HOST=localhost
DB_PORT=5432
DB_NAME=repair_workshop
DB_ADMIN_DATABASE=postgres
DB_AUTO_CREATE=true

PORT=5000
JWT_SECRET=replace-with-long-random-secret-at-least-32-characters
DEFAULT_USER_PASSWORD=123456

EMAIL_USER=your-email@gmail.com
EMAIL_PASS=your-gmail-app-password

TWILIO_ACCOUNT_SID=AC...
TWILIO_AUTH_TOKEN=...
TWILIO_PHONE_NUMBER=+1...
```

Файл `.env` не можна додавати в Git, тому що там зберігаються паролі, токени та приватні ключі.

Для демонстраційних даних краще використовувати тестові телефони та власні email-адреси, щоб випадково не надіслати повідомлення реальним людям.

## Запуск

Встановити залежності сервера:

```bash
cd server
npm install
```

Запустити сервер:

```bash
npm run dev
```

Встановити залежності клієнта:

```bash
cd client
npm install
```

Запустити клієнт:

```bash
npm run dev
```

Адреси після запуску:

- API: `http://localhost:5000/api`

Client API URL for Render:

Create `client/.env` locally or add an environment variable in Render:

```env
VITE_API_URL=https://your-render-backend.onrender.com
```

The frontend falls back to `http://localhost:5000` when `VITE_API_URL` is not set. Requests add `/api/...` in the code.
- клієнтська частина: `http://localhost:5173`

## Основні API-маршрути

Авторизація:

- `POST /api/auth/login` — вхід;
- `GET /api/auth/me` — перевірка поточного користувача.

Замовлення:

- `GET /api/orders` — список замовлень;
- `POST /api/orders` — створення замовлення;
- `PUT /api/orders/:id/status` — зміна статусу;
- `PUT /api/orders/:id/master` — призначення майстра;
- `PUT /api/orders/:id/complete` — завершення ремонту з ціною та деталями;
- `DELETE /api/orders/:id` — видалення замовлення;
- `GET /api/orders/:id/history` — історія статусів.

Склад:

- `GET /api/parts` — список деталей;
- `POST /api/parts` — додавання деталі;
- `PUT /api/parts/:id` — оновлення кількості;
- `DELETE /api/parts/:id` — видалення деталі.

Заявки на деталі:

- `GET /api/part-requests` — список заявок;
- `POST /api/part-requests` — створення заявки майстром;
- `PATCH /api/part-requests/:id/status` — обробка заявки.

Інше:

- `GET /api/masters` — список активних майстрів;
- `PUT /api/clients/:id` — оновлення телефону або email клієнта.

## SMS та Email

SMS надсилається:

- при створенні нового замовлення;
- при завершенні ремонту.

Email надсилається при зміні статусу та при завершенні ремонту. Лист завершення ремонту містить суму до оплати.

Важливо: якщо в `.env` заповнені реальні `EMAIL_*` або `TWILIO_*`, система буде робити реальні відправки. Для тестування використовуйте тільки власні контакти або тимчасово приберіть ці змінні з `.env`.

## Демонстраційний сценарій

1. Увійти як `admin`.
2. Створити нове замовлення.
3. Призначити відповідального майстра.
4. Показати, що майстер бачить тільки свої замовлення.
5. Перевести замовлення у `діагностика` та `ремонт`.
6. На сторінці фінансів задати середній чек.
7. Перевести замовлення у `виконано`.
8. У формі завершення показати автоматично підставлену вартість роботи.
9. Додати використані деталі та завершити ремонт.
10. Показати списання деталей зі складу.
11. Показати суму до оплати в деталях замовлення.
12. Видати замовлення клієнту від імені адміна або менеджера.
13. Відкрити історію статусів.
14. Увійти як майстер і створити заявку на потрібну деталь.
15. Увійти як адмін і обробити заявку через іконку сповіщення.
16. Перейти у звіти та фінанси.
